**Requisitos:** RNF-08 · A02, A05 — **Automatizada:** `pytest -k cp32 -v` (redirección de la propia aplicación, HSTS y cookie segura)

| # | Paso | Resultado esperado |

## Revisión OWASP Top 10 2021

Marca cada riesgo como Cumple, No cumple (registra un DEF) o No aplica.

| Riesgo | Control en ControlGastos | Cómo verificarlo | Resultado |
|---|---|---|---|
| **A01** Pérdida de control de acceso | Todas las rutas exigen sesión, salvo `/login` y `/salud`. Hay roles (el administrador no ve gastos) y un dato ajeno responde 404. | CP-29. | |
| **A02** Fallas criptográficas | Contraseñas con Argon2id y rehash; HTTPS con HSTS en producción. La app no arranca en producción con una `SECRET_KEY` de menos de 32 caracteres. Cookies Secure en producción. | CP-31, CP-32 y `pytest tests/integration/test_configuracion.py -v`. | |
| **A03** Inyección | Solo consultas con el ORM y parámetros. Jinja2 escapa todo el texto y ninguna plantilla usa `\|safe` con datos del usuario (lo revisa una prueba automática). | Registra un gasto con la descripción `<script>alert(1)</script>`: debe verse como texto, sin ninguna alerta. En Mis gastos busca `' OR 1=1 --`: "No hay gastos con estos filtros", sin errores. | |
| **A04** Diseño inseguro | Bloqueo de 15 minutos tras 5 intentos (CP-03). Máximo 10 intentos de inicio de sesión por minuto por IP. Las reglas de negocio (montos, fechas) se validan en el servidor. | Intenta ingresar 11 veces en menos de un minuto con un correo que no existe: el 11.º intento muestra "Demasiados intentos" (429). | |
| **A05** Configuración de seguridad incorrecta | Sin modo de depuración en producción. CSP `default-src 'self'` sin scripts en línea, cabeceras de seguridad y páginas de error sin trazas. | `curl.exe -I http://127.0.0.1:5000/login` debe mostrar `Content-Security-Policy: default-src 'self'; img-src 'self' data:`, `X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin` y `Permissions-Policy: browsing-topics=()`. Abre `/no-existe`: "Página no encontrada", sin detalles técnicos. | |
| **A06** Componentes vulnerables y desactualizados | Versiones fijas en `requirements.txt`. Librerías de interfaz locales con versión exacta (`app/static/vendor/`). | `pip list --outdated` y revisión de los avisos de seguridad de cada paquete (por ejemplo, con `pip-audit`, que se instala aparte). Cada hallazgo se registra como DEF. | |
| **A07** Fallas de identificación y autenticación | Sesión de 30 minutos que se renueva con cada uso y se regenera al ingresar. Cookies HttpOnly y SameSite=Lax (Secure en producción). Sin "recordarme". Política de contraseñas y mensaje genérico ante datos incorrectos. | CP-01, CP-02 y CP-05 a CP-07. | |
| **A08** Fallas de integridad del software y de los datos | CSRF en todos los formularios y acciones POST. Dependencias con versión fija y nada cargado desde CDN. | CP-30. | |
| **A09** Fallas de registro y monitoreo | Bitácora con usuario, fecha, hora e IP de INICIO_SESION, CIERRE_SESION, LOGIN_FALLIDO, CREAR, MODIFICAR, ELIMINAR, ACTIVAR, DESACTIVAR y RESTABLECER, sin contraseñas. `/salud` para el monitoreo. | `SELECT accion, entidad, usuario_id, ip, creado_en FROM auditoria ORDER BY id DESC LIMIT 20;` | |
| **A10** Falsificación de solicitudes del lado del servidor (SSRF) | No aplica: la aplicación no descarga ni consulta direcciones que indique el usuario. | Revisión del código: no hay peticiones HTTP salientes. | |
